# OrangeLen 产品与架构边界审查

日期：2026-10-08。审查基线：`24a145d`，并核对本轮工作区。范围：宿主、Finder 扩展、共享阅读器、各格式解析、目录、图片下载与授权、阅读状态、构建发布及验收文档。

结论：格式覆盖已经较广，当前最需要补的是**内容身份正确性、失败/取消后的状态一致性、解析后的资源预算、恢复路径**。有些问题会显示错误内容，不能靠“不支持某格式”的提示解释。此次为检查交付，没有修改产品实现、安装、提交或推送。

## 一、12 项已复现的问题或预算缺口

### 1. P1：SQLite 生成列导致列名与数据错位

**触发**：数据库表中间包含生成列，例如 `a, doubled GENERATED ALWAYS AS (a*2), label`。

**复现**：写入 `a=7, label='orange'` 后，读取到的列名为 `[a, label]`，行值为 `[7, 14, orange]`。原生表按列下标显示，`label` 列实际显示 `14`，真正的 `orange` 没有对应列。排序又按列名执行，进一步造成“排序的列”和“看到的值”不一致。

**依据**：[DatabaseDocument.swift:80](../Packages/OrangeLen/Sources/OrangeLenCore/DatabaseDocument.swift#L80) 用 `PRAGMA table_info` 建立列结构，103 行查询却用 `SELECT *`；[DatabaseController.swift:89](../Packages/OrangeLen/Sources/OrangeLenUI/DatabaseController.swift#L89) 按数组下标展示。

**修复与验收**：以实际 statement 返回的列顺序为准，结合 `table_xinfo` 补充元数据，或生成明确列清单。覆盖 VIRTUAL/STORED 生成列位于首/中/尾、排序、复制和分页；每行字段数和列数必须一致。

### 2. P1：坏 Notebook 继续显示上一份 Notebook，错误提示被隐藏

**触发**：先成功打开 Notebook A，再打开损坏的 Notebook B。

**复现**：B 已返回解析错误，正文仍然是 A 的 `OLD PRIVATE CONTENT`。错误只写入 `message`，而连续 Notebook 模式把包含这个控件的左栏隐藏；父阅读器仍显示泛化的容器状态。用户无法可靠辨别正文属于哪个文件。

**依据**：[CollectionController.swift:46](../Packages/OrangeLen/Sources/OrangeLenUI/CollectionController.swift#L46)、154、243 行：`cancel()` 关闭任务但不清空子阅读器正文，顶层失败只修改左侧消息。

**修复与验收**：开始新容器请求立即切换为包含文件名的加载态；失败和空结果必须在可见正文区呈现。覆盖 A→坏 B、A→空容器、连续 gzip 模式、快速切换；B 失败时不能把 A 正文当 B 展示。若产品选择保留旧快照，必须显式标注其来源并提供清除。

### 3. P1：SQLite 切表失败后，旧表数据仍可被当成新表操作

**触发**：先打开可读的表，再切到包含超过单值预算的表，或切表查询失败。

**复现**：选择器已经是 `oversized`，错误出现后 `page` 仍保留上一张表的 `7/14/orange`，且表格重新启用。旧数据仍可显示、选择、复制。

**依据**：[DatabaseController.swift:48](../Packages/OrangeLen/Sources/OrangeLenUI/DatabaseController.swift#L48)：加载前没有清空旧页；63 行无条件启用表格；81 行失败分支只更新状态和上一页按钮。

**修复与验收**：将表名、排序、偏移和 page 作为同一份已提交视图状态。切表失败清空并显示错误，或回滚选择器并明确标记旧表；不能只更新标题。覆盖切表、翻页、排序、自动刷新失败及复制内容归属。

### 4. P1：JSON 节点数量预算没有限制路径字符串膨胀

**触发**：一个很长的父键名下有大量短子节点。

**复现**：输入仅 **32,974 字节**、100 个数组成员，叶节点保存的完整路径合计已经 **3,277,690 字节**，约 99 倍；仍远低于现有输入、深度和节点上限。这是路径文本的字节总和，不是测量的进程内存峰值。

**依据**：[JSONParser.swift:141](../Packages/OrangeLen/Sources/OrangeLenCore/JSONParser.swift#L141)、151 行：每个子节点都拼接并保存完整父路径。节点/输入分别有界，不代表二者乘积有界。

**修复与验收**：节点保存父引用和单段键，点击“复制路径”时才生成完整路径，并限制单路径和模型累计字节。增加长键×宽数组、长键×深嵌套组合测试；定义模型峰值内存预算，不能仅验节点数。

### 5. P1：Office 共享字符串展开先分配、后检查正文预算

**触发**：XLSX 的多个单元格引用同一段长共享字符串。

**复现**：最小 ZIP/XML 夹具 **4,236 字节**，输出 **100,682 字节**。更关键的是实现先为所有单元格拼接 `parts`，再 `joined` 并追加整张工作表，最后才检查 5 MiB。共享字符串表和工作表 XML 均合法且小，并不能限制展开后的总输出。

**依据**：[OfficeContentPreview.swift:24](../Packages/OrangeLen/Sources/OrangeLenCore/OfficeContentPreview.swift#L24)、26、68–71 行。XML 回调没有显式应用节点、深度、单元格数量及累计输出预算。

**修复与验收**：在每次追加文本/单元格之前计费，包括共享字符串替换、地址、公式说明及换行；预算用尽即中止解析，保留清晰的部分/失败状态。覆盖一长字符串被大量重复引用和深层 XML；用有上限的压力用例验证中止发生在大规模分配前。本轮没有尝试制造 OOM。

### 6. P2：原生 Word/ODT 导入没有消费 ZIP 条目的受限结果

**触发**：一个 Office ZIP 成员超过单条目大小或压缩比预算，但声明总展开量仍未超过总预算。

**复现**：包含 6,000,000 字节成员的压缩 ZIP，`ArchiveDocument.parse` 成功返回，成员标为“条目大小或压缩比超过预算”；`archive.read` 正确拒绝。原生文档导入路径却丢弃 parse 返回值，继续把原始 ZIP 交给系统导入器。

**依据**：[ReaderSystemPreview.swift:100](../Packages/OrangeLen/Sources/OrangeLenUI/ReaderSystemPreview.swift#L100)、[ArchiveDocument.swift:86](../Packages/OrangeLen/Sources/OrangeLenCore/ArchiveDocument.swift#L86)。当前预检确实检查中央目录及声明总量；不能将它理解为已验证全部成员实际展开、CRC 或受限策略。

**修复与验收**：定义原生导入专用预算并明确执行，至少拒绝不可接受的 blocked 成员；需要验证的部件在有界解压后检查。系统导入器还需要独立时间/内存与外部资源行为验收。探针只验证 ZIP 预检契约，使用的夹具不是完整 DOCX，也没有证明系统导入器实际发生越界或攻击。

### 7. P2：关闭或切文件会丢失大文件向前翻页历史

**触发**：开启阅读记忆，进入大文件第 2 页，关闭后重开。

**复现**：正确恢复到字节偏移 65,536，但“上一页”被禁用。保存记录里的 history 已变成空数组。

**依据**：[ReaderController.swift:499](../Packages/OrangeLen/Sources/OrangeLenUI/ReaderController.swift#L499)：先 `pageHistory = []` 再 `savePosition()`。切文件时 291–293 行也先修改 history 再保存旧文档。另外，SettingsStore 只保留末 128 个页偏移，长文档重开后无法无限向前回退。

**修复与验收**：先保存完整的旧文档状态，再重置；分页位置封装为一份不可拆开的值。明确超过 128 页后的回退策略，提供返回开头/重新定位入口。测试关闭、切文件、手动重载、重开第 2/130 页与 UTF 边界。

### 8. P2：自动刷新遇到文件缩短，会掉入无正文、无分页按钮的状态

**触发**：阅读日志等大文件第 2 页时，文件被截断或原子替换成短文件。

**复现**：继续用旧偏移读取，显示“超过安全预算：分页位置”，`source` 为空且页栏隐藏；自动刷新已记录新修订，不会自行恢复。用户需要手动重载，而当前错误没有解释“文件缩短”。

**依据**：[ReaderController.swift:643](../Packages/OrangeLen/Sources/OrangeLenUI/ReaderController.swift#L643)、[AccessBroker.swift:77](../Packages/OrangeLen/Sources/OrangeLenCore/AccessBroker.swift#L77)。

**修复与验收**：新修订先验证字节偏移，失效时回首页或最近合法页，并提示内容已缩短。对 UTF-8/16 按标量边界重新定位；同样覆盖新修订改变编码、文件删除后重建、日志轮转和连续保存。

### 9. P2：非首分页开头的 U+FEFF 被误当文件 BOM 删除

**触发**：UTF-8 文件的真实内容字符 U+FEFF 恰好位于页首。

**复现**：首段 16 个 `a`，紧接 U+FEFF 和正文；使用 16 字节页读取时，拼接两页不等于原文。字节范围继续推进，但第二页内容字符被悄悄删除。正式 64 KiB 页存在相同机制。

**依据**：[AccessBroker.swift:120](../Packages/OrangeLen/Sources/OrangeLenCore/AccessBroker.swift#L120) 每页调用会去掉 BOM 的 `decode`，153 行没有区分绝对文件偏移。

**修复与验收**：首文件头只识别一次编码；后续页按固定编码解码，不再自动移除 UTF-8 BOM 字节。验证页首 U+FEFF、真实首 BOM、UTF-16 字节序和逐页拼接等于完整解码结果。

### 10. P2：顶层“取消加载”没有取消容器子任务

**触发**：父 Reader 拥有正在工作的 Collection/Archive/Database 子控制器，触发父级取消。

**复现**：父 `cancelLoad()` 返回后，Collection 的 Cancellation token 仍通过 `check()`。这是一项组件调用复现，未声称所有容器界面当前都有可点击的父取消按钮；实际上容器模式还隐藏了父工具栏，取消入口本身也不统一。

**依据**：[ReaderController.swift:506](../Packages/OrangeLen/Sources/OrangeLenUI/ReaderController.swift#L506)：只取消自身及 folder；相比 `close/loadFile` 缺少三个子控制器的取消。

**修复与验收**：建立根请求到所有子任务的取消传播，确保用户可见的取消入口覆盖容器。取消后既不能继续发布正文，也不能继续联网/解压/查询；保留已提交快照时需明确标注。同步系统调用不能立即抢占的情况另设隔离与超时策略。

### 11. P2：取消目录加载后 loading 标志不复位，不能重新展开恢复

**触发**：目录枚举期间取消，再尝试加载原节点。

**复现**：节点保持 `loading=true, loaded=false`；再次 `load(node)` 被入口 guard 拒绝，任务数组仍为空。必须重新打开目录树才能恢复。

**依据**：[FolderController.swift:68](../Packages/OrangeLen/Sources/OrangeLenUI/FolderController.swift#L68)、71、79 行：取消改变 generation，异步回调在清理 loading 之前退出；`cancel()` 本身也没清理节点状态。

**修复与验收**：节点状态统一为 idle/loading/loaded/failed/cancelled，取消在主线程同步清理对应节点，不依赖过期回调。覆盖根节点、子目录、继续加载、超时/权限失败及取消后重试。并行修改的持续统计分支仍复现本问题。

### 12. P2：ZIP 路径别名在树中折叠，静默覆盖一个成员

**触发**：归档同时包含 `folder/a.txt` 与 `folder//a.txt`。

**复现**：解析器保留两条合法且原始名字不同的记录；目录树按去空段的路径构建，最后只有一个叶节点，entry 被后者覆盖。列表总数和可访问成员不一致，用户不能查看第一个成员。

**依据**：[ArchiveDocument.swift:16](../Packages/OrangeLen/Sources/OrangeLenCore/ArchiveDocument.swift#L16) 与原始 names 去重；[ArchiveController.swift:75](../Packages/OrangeLen/Sources/OrangeLenUI/ArchiveController.swift#L75)、87 行规范化构树后直接替换 entry。

**修复与验收**：解析器和 UI 使用统一的路径身份规则，遇规范化冲突明确报错或展示冲突节点；不能静默覆盖。增加重复分隔符、`.`、文件/目录同名和文件作为父路径的测试。此问题是展示身份冲突，本轮未发现磁盘解压路径穿越。

## 三、产品经理视角需要补齐的验收契约

1. **入口契约**：同格式分别记录 Finder 单文件、Finder 文件夹、宿主、归档内四个入口；支持正文、内容降级、系统交接、不支持分开。不要用一个“支持”勾覆盖全部入口。
2. **状态契约**：每个视图都应有未开始、加载、成功、部分、空内容、失败、取消、失效旧快照的可见状态。标题、正文、复制、搜索必须来自同一个已提交文档身份。
3. **数据保真契约**：原文、解码文本、渲染文本、生成摘要区分清楚。SQLite 的 NULL 与文字 `NULL`、BLOB 与同形文字应能辨别；CSV/TSV 含制表符/换行时复制行应有明确转义规则。原始 JSON/Notebook/HAR 的数字词面、重复键与合成展示也要标清。
4. **分页契约**：页内搜索/复制限制已明确，可以保留；但必须能回首页、恢复上一页、处理文件缩短/编码变化和超过记忆历史窗口。按钮翻页本身不算新缺陷。
5. **Office 内容契约**：明确内部文件顺序、隐藏部件、工作表显示名、日期/数字格式、过期公式缓存和未支持对象的说明。当前“无原始版式”合理，但不能让原始序列数或隐藏页被误解为用户正常看到的文档内容。
6. **失败后的操作契约**：每种错误至少有一个可用出口：重试、回退源码、返回目录、单文件预览或默认应用打开；不能让恢复按钮指向已失效偏移或隐藏的父控件。
7. **授权契约**：授权覆盖哪个目录、哪份文档、什么修订，撤销与宿主崩溃后多久失效，需要可理解的状态；换文档不能带入旧同意。共享 grant 已有实现，接下来验收休眠唤醒、时钟变化、重复授权及权限撤销。
8. **无障碍与窗口契约**：VoiceOver 能读出文件身份、错误、部分结果、页码和加载完成；控件折叠后仍可操作。覆盖深色、高对比、360px 窄窗、多显示器、图像替代文本与真实 Finder 复制。仅 AX 树有控件不等于完整通过。

此前已接受的 Finder 键盘事件限制、系统优先分派、不抢占 `.dev/public.data`、不执行文档 HTML/脚本、Notebook 连续阅读、不恢复专注阅读，都没有重新列为缺陷。未支持的 RAR/7z/MOBI 等属于功能范围，不应挤占上述正确性修复。

## 四、建议执行顺序和完成标准

**第一批：内容正确性。** 修复 1/2/3，保证任何失败或切换都不会错误标注旧数据；随后修复 9/12 的保真与身份冲突。以生成列、坏文件连续切换、查询失败后复制、路径别名和 Unicode 拼接回归作为退出条件。

**第二批：预算闭环。** 修复 4/5，并明确执行 6 的导入预算；增加累计输出、模型路径、在途任务预算。退出条件是合法但极端的输入可在上限前中止并恢复交互；不能只检查压缩文件大小。

**第三批：生命周期与恢复。** 修复 7/8/10/11，统一根请求取消与子视图状态；完善重新打开、刷新、日志轮转、目录取消再加载、设置并发的测试。

**发布前验收。** 基于最终代码跑正式回归、签名构建及真实 Finder 关键路径；补冷启动/首帧/交互就绪、峰值内存、长期切换、云盘/外置盘与辅助功能。Developer ID、公证、Gatekeeper、多 macOS/Intel 仍需要对应环境与证据，本轮没有代跑或视作通过。

推荐架构收敛为一份 `PreviewSession`：统一持有 document identity、revision、generation、取消树、预算、已提交视图状态和恢复信息；各格式只实现有界读取/解析/展示适配。它解决的是本轮重复出现的跨控制器状态分散问题，不要求立即重写现有 Core/UI 分层。
